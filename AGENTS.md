# go-klavis

Unofficial Go client for the Klavis AI API, generated from the OpenAPI document Klavis AI publishes. If you only want to use the client from an agent, read [.agents/skills/go-klavis/SKILL.md](.agents/skills/go-klavis/SKILL.md) instead; this file is about changing the code.

## Architecture

One generated package, `klavis`, at the module root, driven by `gen.go`:

`scripts/fetch-spec.sh` downloads `https://api.klavis.ai/openapi.json` to `api/openapi.json`. `scripts/patch-spec.sh` merges duplicate schemas into `api/openapi.fixed.json`, then oapi-codegen runs with `config.yaml` and writes `client.gen.go`. The document stays OpenAPI 3.1.

## Stack

- Go 1.26.10.
- oapi-codegen, pinned as a `tool` dependency in `go.mod`.
- Runtime: `github.com/oapi-codegen/runtime`.

## Layout

- `gen.go`, `config.yaml`, `client.gen.go`: the package.
- `aliases.go`: deprecated aliases for type names earlier releases generated.
- `client_test.go`, `example_test.go`: tests, including the README example.
- `scripts/`: spec download, duplicate schema merge, lint and security scan scripts.
- `api/`: the downloaded spec, gitignored.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec and regenerate
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- The upstream document is OpenAPI 3.1.0, API version 0.1.0. oapi-codegen 2.8.0 reads its nullable unions, constants and examples directly.
- The API serves the same model under a plain and a module-qualified name (`sandbox__schemas__google_calendar__GoogleCalendarEvent-Input` and similar), and which module gets the plain name changes between responses with no version change. `patch-spec.sh` merges identical copies into the plain name so generated types stay stable, and fails when they differ. `aliases.go` keeps the type names earlier releases generated as deprecated aliases; keep them.
- `config.yaml` maps unformatted numbers to `float64`, resolves type name collisions and prefixes enum values. Dropping these options changes generated types or can produce duplicate Go identifiers.
- Operation IDs determine method names. Sandbox and Strata operations often have long generated names. Check `client.gen.go` before using a name in docs or tests.
- Bearer authentication is explicit through `WithRequestEditorFn`. Production hosts are `https://api.klavis.ai` and `https://api.eu.klavis.ai`. Some OAuth endpoints have no security declaration.
- `CallToolResponse` and `ListToolsResponse` can report `Success: false` inside HTTP 200. Check decoded fields as well as HTTP status.
- `GetAllUsersParams.PageNumber` starts at one. `PageSize` accepts one through 1000. Walk pages through `TotalPages` when loading all users.
- `make generate` always downloads the current spec, so it can change the client even when nothing here changed. Review the generated diff before committing it.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When checks fail, Claude edits the repository to fix them, but a fix may not touch paths listed under `fix_protected_paths`: workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
